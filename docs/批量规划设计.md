# 批量规划设计（`crb plan`）

> 目标：老师/同学手里有一批活动（时间、人数、用途），一键得到「哪间空闲教室可用」的方案，
> 确认后批量生成教室借用申请草稿。

## 输入

支持两种格式（见 `examples/plan.example.json`）：

```json
{
  "defaults": {
    "JYDWDM": "400760",
    "JYRXM": "李赫",
    "JYRDH": "13800000000",
    "JSJYLXDM": "02",
    "campus": "3"
  },
  "activities": [
    { "title": "学生社团例会", "date": "2026-09-10", "period": "1-2", "people": 30 },
    { "title": "小型讨论", "date": "2026-09-10", "period": "5-6", "people": 10,
      "preferred_room": "仙Ⅰ-102" }
  ]
}
```

- 也可以直接是活动数组，省略 `defaults`。
- 单条活动可覆盖 `campus / building / room_type / JYDWDM / JYRXM / JYRDH / JSJYLXDM`。

## 算法

对每条活动：

1. **查询空闲教室**：`kxjscx/cxkxjs.do`，参数 `KXRQ/KSJC/JSJC/XXXQDM`（+ 可选 `JXLDM/JASLXDM`），
   节次过滤由服务端完成。
2. **容量过滤**：`SKZWS`（上课座位数，回退 `KSZWS`）≥ `people`。
   - 没有空闲教室 → `no_room`
   - 有教室但容量都不够 → `too_small`
3. **批次内冲突检测**：记录 `(教室名, 日期) -> 已占用节次区间`，
   与本次要申请的节次区间重叠的候选教室会被排除。
4. **选教室**：
   - 有 `preferred_room` 且可用 → 用它；不可用则记录提示并改选；
   - 否则选**容量刚好够用**的（避免占大教室），同名按名称排序。

## 输出

- 默认 **dry-run**：打印方案表（活动/日期/节次/人数/教室/容量/状态），不写系统。
- `--save`：把 `status=ok` 的条目转成借用申请并保存为**草稿**（`TYPE=save`）。
- `--json`：输出结构化结果，供 AI/脚本消费。

## 已知限制

- **学生端不能指定具体教室**：学校按申请分配，`preferred_room` 只会写进用途描述
  （`JYYTMS` 里的「意向：xxx」）和备注 `FJ`，不保证借到。
- 冲突检测覆盖：**本批次内** + **跨批次（自己已有的申请）**。
  - 与自己已有申请时间重叠 → 标记 `duplicate` 并跳过（可用 `--allow-overlap` 强制）；
  - 从已有申请的备注 `FJ` 读取已用教室，避免重复选同一间（仅对工具创建的申请有效）。
  - 拿不到全校/他人的教室占用，无法做全局冲突检测。
- 同一账号在同一时间提交多条申请是否会被系统拦截，尚未实测。

## 后续

- 自然语言活动列表 → plan JSON（可在 skill 层由 AI 完成）。
