# 批量规划设计（`crb plan`）

> 目标：老师/同学手里有一批活动（时间、人数、用途），一键得到「哪间空闲教室可用」的方案，
> 确认后批量生成教室借用申请草稿。

## 输入

支持两种格式（见 `examples/plan.example.json`）：

```json
{
  "defaults": {
    "JYDWDM": "400760",
    "JYRXM": "李赫",
    "JYRDH": "13800000000",
    "JSJYLXDM": "02",
    "campus": "3"
  },
  "activities": [
    { "title": "学生社团例会", "date": "2026-09-10", "period": "1-2", "people": 30 },
    { "title": "小型讨论", "date": "2026-09-10", "period": "5-6", "people": 10,
      "preferred_room": "仙Ⅰ-102" }
  ]
}
```

- 也可以直接是活动数组，省略 `defaults`。
- 单条活动可覆盖 `campus / building / room_type / JYDWDM / JYRXM / JYRDH / JSJYLXDM`。

## 算法

对每条活动：

1. **四项防重**（对齐教师侧脚本）：`preferred_room` 若与**自己已有申请**在
   「日期 + 校区 + 节次 + 教室」四项一致（节次区间有重叠也算），直接标 `duplicate` 跳过，
   不必再查空闲教室。
2. **查询空闲教室**：`kxjscx/cxkxjs.do`，参数 `KXRQ/KSJC/JSJC/XXXQDM`（+ 可选 `JXLDM/JASLXDM`），
   节次过滤由服务端完成。
3. **容量过滤**：`SKZWS`（上课座位数，回退 `KSZWS`）≥ `people`。
   - 没有空闲教室 → `no_room`
   - 有教室但容量都不够 → `too_small`
4. **占用排除**：`(校区, 教室名, 日期) -> 已占用节次区间`，来源是**本批次已分配** +
   **已有申请**（教室取备注 `FJ`，没有则取学校分配后的 `JASMC`）；重叠的候选教室会被排除。
   若候选全被占、且其中某间正是与已有申请四项一致的教室 → 报 `duplicate` 而不是 `no_room`。
5. **选教室**：
   - 有 `preferred_room` 且可用 → 用它（教室名做了归一化，`仙I-102` / `仙Ⅰ-102` 视为同一间）；
     不可用则记录提示并改选；
   - 否则选**容量刚好够用**的（避免占大教室），同名按名称排序。
6. **选中的教室再判一次四项防重**：改选后如果恰好撞上已有申请的那间，同样判 `duplicate`。

## 输出

- 默认 **dry-run**：打印方案表（活动/日期/节次/人数/教室/容量/状态），不写系统。
- `--save`：把 `status=ok` 的条目转成借用申请并保存为**草稿**（`TYPE=save`）。
- `--json`：输出结构化结果，供 AI/脚本消费。

## 已知限制

- **不能指定具体教室**：学校按申请分配，`preferred_room` 只会写进用途描述
  （`JYYTMS` 里的「意向：xxx」）和备注 `FJ`，不保证借到。
- 冲突检测覆盖：**本批次内** + **跨批次（自己已有的申请）**，口径是
  「日期 + 校区 + 节次 + 教室」四项（与教师侧脚本一致）。
  - 四项一致（节次区间有重叠也算）→ 标 `duplicate` 并跳过，可用 `--allow-overlap` 强制；
  - **只是时段重叠、教室不同不算重复**——并行活动（同时间、不同教室或校区）是正常需求；
  - 已有申请的教室证据：优先备注 `FJ`（本工具写入的意向教室），否则 `JASMC`（学校分配后的教室）；
  - 拿不到全校/他人的教室占用，无法做全局冲突检测。
- 同一账号在**同一时间、不同教室**提交多条申请是否会被系统拦截，尚未实测。
